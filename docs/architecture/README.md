# Архитектура

## Назначение

Проект представляет собой учебную Python-библиотеку для декларативного описания и пошагового исполнения взаимодействующих автоматных объектов CIAO. Библиотека не является IDE или визуальным редактором.

## Предварительное разделение ответственности

### Доменная модель

Содержит декларативное описание программы: автоматные классы и объекты, состояния, операции, переходы и соединения. Этот слой не знает об очереди сообщений, цикле Tkinter и текущем состоянии исполнения.

### Инфраструктура исполнения

Проверяет и компилирует декларативную модель, хранит независимое состояние экземпляров, маршрутизирует операции, обрабатывает FIFO-очередь команд и формирует трассу выполнения.

### Визуализация

Содержит необязательные Tkinter-адаптеры, конкретные представления примеров и односторонний экспортер draw.io. Визуализация не изменяет внутреннее устройство runtime; экспортер работает с проверенным `CompiledProgram` без запуска исполнения.

## Согласованная основа декларативного API

- Комбинации `COMMAND`/`QUERY` и `PROVIDED`/`REQUIRED` представлены четырьмя публичными декораторами: `@provided_command`, `@required_command`, `@provided_query`, `@required_query`.
- Внутри они создают одну модель `Operation`; универсальный параметризованный декоратор не является основным пользовательским API.
- `@guard` и `@action` отмечают локальные элементы перехода. Они не являются операциями и не могут быть конечными точками `Connection`.
- `@action(emit=command)` декларирует одну потенциальную required-команду и требует параметр `Emit`; `@action(emits=(...))` внедряет `Emits`. Обычный `@action` capability не получает.
- Переход объявляется через `transition(...)`, содержит не более одного условия и упорядоченный кортеж действий.
- Компилятор проверяет сигнатуры по аннотациям типов: результат `Guard` должен иметь тип `bool`, результат `Action` — `None`, а параметры события должны быть совместимы с запускающей операцией.
- `State(final=True)` задаёт явную финальную семантику для анализа и визуализации, но не останавливает runtime.
- Provided-декораторы принимают необязательный `external=True`. Внешней является только явно отмеченная операция; имя метода не имеет специального значения.
- Роль задаётся выбором Generic-базы: `Automaton[ContextT]`, `ControllerAutomaton[ContextT]` или `ViewAutomaton[ContextT]`. Соответствующие значения `AutomatonRole` — `BASE`, `CONTROLLER`, `VIEW`; роль не влияет на исполнение.

Декораторы сохраняют декларативные метаданные, но не исполняют пользовательский код и не могут доказать чистоту условия.

Компилятор один раз разрешает аннотации операций и сохраняет неизменяемые `OperationSignature` в `AutomatonDefinition`. Инфраструктура исполнения и визуализаторы используют эти проверенные метаданные, не вызывая собственный повторный `get_type_hints()` для операций.

## Контекст автоматного объекта

Пользователь объявляет тип локального состояния наследником `AutomatonContext`. Поля наследника доступны обработчикам напрямую:

```python
@dataclass
class ControllerContext(AutomatonContext):
    values: list[int]
    index: int = 0
    total: int = 0
```

Тип связывается с автоматом через Generic, например `class Controller(ControllerAutomaton[ControllerContext])`. `Runtime` владеет контекстами и создаёт отдельный экземпляр для каждого `AutomatonObject` в каждом запуске. Декларативный класс автомата не хранит текущие значения. Обработчик получает только контекст объекта-адресата; доступ к другим объектам осуществляется через требуемые операции и `Connection`.

Исходящая required-команда явно указывается в метаданных `Action`:

```python
@action(emit=draw)
def publish(self, ctx: ControllerContext, emit: Emit) -> None:
    emit(total=ctx.total)
```

`Emit` уже привязан к команде, объекту-источнику и текущему runtime. Он действует только во время одного вызова `Action`, а команды буферизуются до успешного завершения всего перехода. Для нескольких команд используется `emits[self.command](...)`. Публичный `Automaton.emit(...)` удалён, чтобы компилятор и экспортёр видели полный набор потенциальных исходящих команд.

Требуемый запрос по-прежнему вызывается через `self.query(ctx, self.read_limit)`. Контекст хранит пользовательские поля и закрытую runtime-привязку только для запросов, но не предоставляет доступа к очереди.

Для внешнего наблюдения runtime возвращает снимок состояния, а не изменяемую ссылку на внутренний контекст. Это сохраняет независимость объектов и позволяет повторно запускать одну декларативную программу.

## Протокол учебного примера суммы массива

`SumController` использует промежуточное состояние `publishing`, чтобы публикация снимка была видна в автоматной модели. Переход по `tick` из `running` при допустимом индексе вычисляет очередную сумму, помещает `draw` в FIFO и переводит Controller в `publishing`. `SumView` применяет снимок и асинхронно отправляет обратную команду `draw_completed`; только её обработка возвращает Controller в `running`.

Оба перехода по `tick` из `running` выражают одну бинарную развилку — индекс находится внутри массива либо уже вышел за его границу. Для двух явных ветвей используются взаимно исключающие `Guard`, поскольку MVP не вводит неявные `else`-переходы. При выходе за границу Controller переходит прямо в `done`; отдельной итерации и публикации не происходит.

## Направление зависимостей

```text
пользовательская модель ──> domain
                               ▲
                               │
                         infrastructure
                               ▲
                               │
                     visualization / examples
```

`domain` не импортирует `infrastructure` или `visualization`. Ядро исполняется без GUI.

Подробная согласованная семантика очереди, переходов, ошибок, лимитов и трассы описана в [`runtime-contract.md`](runtime-contract.md).

## Экспорт draw.io

Публичная функция `ciao.visualization.drawio.export_program_drawio(program, path)` выполняет следующий конвейер:

```text
Program → compile_program() → builder → layout → XML writer → .drawio
```

- `compile_program()` вызывается ровно один раз;
- builder читает `AutomatonDefinition`, `OperationSignature` и `routes`;
- layout в две стадии рассчитывает внутренности блоков, затем блоки и межблочные связи;
- writer только сериализует готовые координаты через `xml.etree.ElementTree`;
- запись атомарна: прежний файл заменяется лишь после успешной сериализации временного файла в том же каталоге.

Операции, состояния, Decision-узлы и assembly-связи остаются нативными редактируемыми элементами draw.io. Область автомата имеет белый фон, а состояния и стрелки переходов получают цвет роли (`Controller` — голубой, `View` — зелёный). Отдельный псевдоначальный узел не рисуется: начальное состояние уже задано метаданными `State(initial=True)`.

Внешний `provided` endpoint с `external=True` рисуется lollipop над границей блока и соединяется с исходным состоянием запускаемого перехода. Несвязанные provided/required-операции располагаются у нижней границы и получают короткую подпись именем команды. Имя автоматного объекта и его класса включено в цветную карточку контекста, а не дублируется на белой области блока.

Операция из `Program.connections` представляется составным assembly-интерфейсом в межблочном канале: от блока требующей стороны идёт половина с `halfCircle`, от предоставляющей — половина с `oval`; обе сходятся в общем невидимом узле. Поэтому соединение не пересекает состояния и карточки контекста. Семантические метаданные обеих операций сохраняются на половинах соединения, хотя отдельные endpoint-вершины для них не рисуются.

## Текущее состояние

Реализация находится в пакете `ciao`. Она включает декларативную модель, компиляцию и валидацию, FIFO-runtime, синхронные запросы, трассу, строгий/нестрогий режим и предел `run()`. Цельный исполняемый пример находится в `examples/test_mock_sample.py`, а ключевая семантика покрыта тестами в `tests/`.

Необязательный пакет `ciao.visualization` экспортирует общий адаптер неизменяемых событий runtime в цикл Tkinter через `after` и функцию экспорта draw.io. Конкретные элементы интерфейса суммы массива не объявляются общими виджетами библиотеки: составное представление `ArraySumView` находится в `ciao.visualization.array_sample` и подключено в `examples/array_sum_tk.py` без изменений ядра. Пример экспорта находится в `examples/export_drawio.py`.
